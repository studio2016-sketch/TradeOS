# Local-only scoped audit candidate

**Latest local follow-up:** `private-audit-oidc-candidate.md` describes a secretless OIDC alternative now implemented locally. Its candidate workflows supersede the stored-secret workflow setup described historically below. No alternative is activated or deployed. Browser access subsequently became available; owner sign-in remains unverified while an Apple verification handoff is pending.

## Why owner cookies are not used in GitHub Actions
The old workflows printed raw research/model responses to public Actions logs. Adding an owner cookie would restore HTTP success while re-exposing private research and granting broad account access. This candidate does neither.

A separate 256-bit bearer capability is accepted only at `/api/private-runtime-audit` and the fixed-scope `/api/private-detailed-audit` and `/api/private-market-audit` described below. It cannot authenticate owner pages, any research API, or a mutation route. The heartbeat-only endpoint returns fixed-schema booleans for DB connectivity and stored ingestion/research heartbeat recency. It does not retrieve broker accounts, positions, balances, model results, or forecast rows; it does not write anything. Missing/invalid configuration fails closed. Only the SHA-256 of the credential is required server-side. No credential was generated, uploaded or configured.

## Proposed configuration (requires owner authorization before activation)
- Generate a fresh random 32-byte lowercase hex credential privately.
- Save its SHA-256 as `TRADEOS_RUNTIME_AUDIT_TOKEN_SHA256` for the intended Vercel environment only. Never reuse `CRON_SECRET`, auth cookie secret, or a provider key.
- Save the credential as `TRADEOS_RUNTIME_AUDIT_TOKEN` in a protected GitHub environment `tradeos-runtime-audit`, restricting deployment branches to main and reviewing who can modify workflows/environment policies.
- The new workflow has no PR trigger, only main schedule/manual dispatch, minimal contents-read permission, no persisted checkout credentials, fixed-origin HTTP with redirects disabled, and no raw response logging. Run only after the privacy boundary is deployed; current production still allows anonymous research reads and should fail the check.
- To revoke, remove/rotate the server-side hash. Never enable a fallback to owner cookies or public research reads.

## Detailed source/model/graph replacement (local follow-up)
Three existing scheduled workflows now use the dedicated `/api/private-detailed-audit` endpoint with one of three fixed scopes: `sources`, `models`, `graph`. The same private service computations used by the owner API routes are shared internally; the owner routes retain their existing owner guard and do not accept the audit capability. No arbitrary symbol, URL, query or module is accepted by the new endpoint. The response contains only an exact allowlist of check identifiers and PASS/FAIL/UNAVAILABLE, never source payloads, graph relationships, model metrics, amounts, credentials, counts or error strings. Failures/timeouts produce unavailable checks; no broad success fallback exists.

Retained assertions cover source report presence, broker configuration diagnostic shape, market uncertified status, provider clock shape; research-only model/provenance/trial/factor/replay semantics; independent-graph policy, predictive-authority denials, provenance and scientific promotion denials. Source availability or model validation is not inferred from a passing contract assertion. Raw diagnostic values formerly printed to public logs are deliberately not published. Existing core computations are moved without behavioral changes into internal server modules and used by both owner routes and projections. This avoids a second, drifting implementation of the financial logic.

The new detailed scopes execute the same observational service probes as the prior workflows. Some can populate provider caches/ingestion metadata, as already noted. Unlike the heartbeat-only endpoint, these are **not zero-write database probes**; they do not expose arbitrary writes, portfolio actions or trade execution. Credential configuration approval must disclose this expanded fixed diagnostic scope. No runtime capability exists until the owner authorizes its setup.

Remaining migration gaps: brokerage readiness's future-next-session assertion; market-hours time-separated quote advancement; authenticated desktop/iOS browser flows; and manual market smoke checks still require adaptation. The old anonymous graph-ingestion POST test is not executed by the new runner, which intentionally sends no state-changing requests. Anonymous GET account/research denial is retained. Do not claim those gaps are verified or that this follow-up alone makes release ready. No owner login, deployment, provider changes or credential setup were performed.

The 55-second detailed audit timeout bounds waiting for a response; it does not cancel provider/database operations already in flight. Those retain their existing bounds and may finish cache/ingestion updates after the caller receives 503. This limitation requires consideration before scheduling frequency or production activation; no cancellation guarantee is claimed.

Fixed availability checks retain degradation visibility without publishing counts: source observations, market observations, historical bars, model evidence and factor evidence report PASS or UNAVAILABLE separately from contract/safety assertions. Missing evidence is not silently passed, and evidence presence is not evidence of validity or sufficient sample depth.

## Clock readiness and time-separated advancement (local follow-up)
The brokerage-readiness and market-advancement schedules now use fixed scopes on `/api/private-market-audit`. The capability is not accepted on the ordinary market/chart APIs. The readiness check reads the official clock using a strict adapter that rejects missing or malformed source timestamps and non-boolean open status rather than inventing timestamps. It distinguishes account-read configuration presence from enabled status; neither establishes broker account connectivity or trading permission.

The advancement scope requires a fresh official open clock, both SPY and QQQ observations, a real 90-second wait, another fresh/open clock, and same-source strictly advancing timestamps with non-future ages no greater than 3 minutes. Exact timestamp parsing avoids lexical timezone ordering. Unlike the old loop, a missing symbol cannot be omitted and allow the other symbol alone to pass. A valid closed-market clock returns explicit NOT_RUN_MARKET_CLOSED, not a claim that advancement succeeded. Invalid/missing/stale clock returns unavailable, never a closed-market skip. Chart presence is checked separately; no SIP entitlement or model certification is inferred.

The endpoint requests a 180-second runtime with a 155-second response deadline. **Hosting support for that duration has not been verified or changed.** It must be checked before release; a short-duration deployment will make the audit unavailable, not silently shorten the 90-second observation interval. Expiry prevents starting new phases, but provider requests already in flight are not retroactively canceled. Existing provider-cache/ingestion side effects remain possible. No live clock/provider run was performed in this work.

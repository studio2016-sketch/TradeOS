# Expert source leads are not verified consensus

The original study uses a fixed cohort of twenty practitioners and a threshold of seventeen individually supported positions on one narrowly defined principle. It is not an audited worldwide performance ranking, and consensus cannot establish predictive usefulness or trading authority.

`countDocumentedSupport` is retained as a legacy source-lead tally. `supporters` and `mechanicalThresholdMet` describe only the supplied leads. The function always returns `verified85Percent: false`, `notEstablished: true` and `status: UNVERIFIED`: its input has no reviewed passages, individual attribution review or contradiction adjudication. A URL alone cannot supply those assurances. No existing seed is upgraded to verified evidence.

For each individual and exact principle:
- An explicit mixed stance, or both supporting and contradicting records, is mixed and cannot support the tally.
- A contradicting record vetoes support even with an unresolved source URL; missing source validation must not hide potentially adverse evidence.
- Unrecognized stance values prevent affirmative counting and appear as unresolved.
- Only otherwise unopposed supports with a parseable HTTPS source without embedded credentials are counted as source leads.
- Unknown and related institutional research do not vote. Other principles and outsiders do not affect the tally. Duplicate records never add people.
- Supporting, contradicting, mixed, unresolved and unknown counts partition the fixed twenty-person cohort.

A future reviewed-evidence contract must carry source passages and locations, attribution, scope and dated review provenance, plus an explicit conflict-adjudication process. Do not turn this mechanical threshold into a verified status. Separately validate any resulting research hypothesis against point-in-time data and costs. Nothing here changes learning completion, data collection, certification or order permissions.
